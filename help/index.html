    01MOKKEDAの考え方

    MOKKEDAは、サイトに来た人の状況に合わせて「出すもの」を切り替えるツールです。タグを1本入れると計測がはじまり、そのうえで接客（モーダル・バナーなど）を配信します。

    まず覚える5つの言葉

    ワークスペース契約の単位。会社・事業の箱。この中に複数のサイトとメンバーが入ります。
    サイト計測・配信する対象のドメイン。サイトごとにタグと公開キーが発行されます。
    テンプレート見た目の型。モーダルやバナーのHTML・CSSを持ちます。使い回す前提のパーツです。
    アクションテンプレートに文言・画像・クーポンを入れた「中身」。1つの出し物にあたります。
    シナリオどのページで、いつ、誰に、どのアクションを出すかの設定。実際に配信を決めるのはここです。
    迷ったらこの順番

    テンプレート（型）→ アクション（中身）→ シナリオ（配信条件）。テンプレートは最初に用意されているものを使えばよいので、ふだんの運用は「アクションを作る → シナリオで出す」の2ステップで回ります。

    02最初の設定とSDK設置

    サイトを登録してタグを貼ると計測がはじまります。ここが終わらないと、他のどの機能も動きません。

    サイトを登録する

    1. サイドメニューの 設定 › サイト を開きます。
    2. サイト名と、計測するドメインを登録します。
    3. 保存すると サイトID と 公開キー が発行されます。

    公開キーはタグに書く値で、ページのHTMLに出るため秘密情報ではありません。ただし他人のサイトに貼られると計測が混ざるので、むやみに配らないでください。

    埋め込みタグを貼る

    サイト詳細の「埋め込みタグ」から、環境に合わせて3種類を切り替えられます。SITE_ID と PUBLIC_KEY は画面に表示される実際の値に置き換わります。

    通常のサイト（direct）

    <script
  src="https://app.mokkeda.com/sdk.js"
  data-site-id="SITE_ID"
  data-site-key="PUBLIC_KEY"
  defer
></script>

    Shopify（テーマに貼る場合）

    {% comment %}Mokkeda{% endcomment %}
<script
  src="https://app.mokkeda.com/sdk.js"
  data-site-id="SITE_ID"
  data-site-key="PUBLIC_KEY"
  defer
></script>

    GTM・タグマネージャ経由（gtm）

    <script>
(function() {
  var s = document.createElement('script');
  s.src = 'https://app.mokkeda.com/sdk.js';
  s.setAttribute('data-site-id', 'SITE_ID');
  s.setAttribute('data-site-key', 'PUBLIC_KEY');
  document.head.appendChild(s);
})();
</script>
    貼る場所

    全ページの <head> 内が基本です。サンクスページ（購入完了）にも必ず入れてください。ここが抜けると購入と売上が計測されません。

    計測できているか確認する

    タグを貼ったら自分でサイトを開いてみて、流入計測 の「訪問者」タブに自分の訪問が出るかを見てください。数分で反映されます。出ない場合は 困ったとき を確認してください。

    03接客をつくる3層

    MOKKEDAは「見た目」「中身」「配信条件」を分けて持ちます。分かれているぶん最初は遠回りに見えますが、同じ型を何度も使えるので運用が速くなります。

    テンプレート見た目の型。HTML・CSS・JSを持つ。モーダル／バナー／トースト／ランチャー／質問接客／プッシュ通知の6タイプ。
    アクションテンプレートを選んで、タイトル・本文・画像・リンク・クーポンコードを入れたもの。実際にお客様が見る1つの出し物。
    シナリオアクションを「どのページで・いつ・誰に」出すか。A/Bテスト、CV条件、優先度もここ。複数アクションをまとめて持てる。
    よくある勘違い

    アクションを作っただけでは配信されません。シナリオに追加して、シナリオを稼働状態にするまで、お客様の画面には出ません。

    04テンプレート

    見た目の型を管理する画面です。ふだんは一覧を見るだけで足りますが、独自デザインを入れたいときにここを編集します。

    6つのタイプ

    タイプ出かた向いている用途
    モーダル画面中央のポップアップ。オーバーレイで全体を覆うクーポン訴求、初回訪問者への案内、アンケート。インパクト大
    バナー画面下に固定される帯。スクロールしても消えないセール告知、送料無料ライン、常時出しておきたい情報
    トースト画面隅に出る小さい通知「残り3点」「クーポンあります」など、邪魔せず伝えたいこと
    ランチャー画面隅に常駐するボタン。押すとモーダルが開くいつでも開ける相談窓口、クーポン置き場
    質問接客選択肢付きの質問カードお客様の好みを聞いて次の接客に使う（7章）
    プッシュ通知画面表示なし。通知の購読を促すダイアログだけWebプッシュのオプトイン取得（12章）

    標準テンプレートから作る

    一覧の「標準テンプレートから作成」から、MOKKEDAが用意した型を自分のワークスペースに複製できます。複製したものは自由に編集できます。元の標準テンプレートは変わりません。

    差し込み変数

    テンプレートのHTML・CSS・JSには {{キー}} の形で差し込み口を書けます。アクション編集画面に、そのキーの入力欄が自動で出ます。

    書きかた意味
    {{title}} {{body}}タイトル・本文など、アクションの基本項目
    {{coupon_code}}クーポンコード
    {{任意のキー}}独自の追加フィールド。アクション側に入力欄ができる
    {{#if キー}}…{{/if}}値があるときだけ出す

    特別な属性

    属性はたらき
    data-cx-close押すと閉じる。×ボタンに付けます
    data-cx-copy押すと値をコピーする。クーポンのコピーボタンに
    data-cx-launcher-open押すとランチャーのモーダルを開く
    data-cx-choices質問接客で、選択肢が差し込まれる位置
    編集中のプレビュー

    HTMLエディタの右側にリアルタイムでプレビューが出ます。コピーボタンや閉じるボタンの動きもプレビュー上で再現されるので、保存前に押して確かめてください。

    05アクション

    お客様が実際に見る1つの出し物です。テンプレートを選び、文言と画像を入れて作ります。

    作るときに決めること

    項目内容
    アクション名管理用の名前。お客様には見えません。後から探せる名前にしてください
    サイトどのサイト向けか
    表示タイプモーダル／バナー／トースト／ランチャー／インライン
    テンプレート見た目の型。未選択なら既定の見た目になります
    タイトル・本文表示される文言
    リンクURL・ボタン文言CTAボタンの行き先と文字
    クーポンコード入れると売上の帰属に使われます（下記）
    閉じるボタン文言「閉じる」「あとで」など

    インライン表示（ページに埋め込む）

    ポップアップではなく、ページの中に差し込みたいときに使います。

    項目内容
    表示位置セレクタ差し込む場所のCSSセレクタ（例 .product-form）
    挿入位置その要素の前・後・中の先頭・中の末尾
    スタイル適用方法サイト側のCSSとぶつかるときに切り替えます
    クーポンコードは入れておく価値があります

    アクションにクーポンコードを入れておくと、購入時にそのコードが使われていれば確実にその施策の売上として計上されます。クリックの取りこぼしに関係なく紐づくので、売上貢献を正確に見たい施策では必ず入れてください。

    アーカイブ

    使わなくなったアクションはアーカイブします。アーカイブしたアクションは配信されなくなり、シナリオの選択肢にも出なくなります。過去の実績は残ります。

    06シナリオ

    配信を決める中心の画面です。「① 基本」「② いつ表示？」「③ 誰に表示？」の3ステップで設定します。

    ① 基本 — 何を表示するか

    シナリオ名と、表示するアクションを選びます。アクションは複数追加できます（A/Bテストは③で設定します）。質問接客を使う場合は、ここで質問を選びます。

    ② いつ表示？

    発動タイミング

    種類いつ出るか
    ⚡ 即時ページ表示直後
    ⏱ 滞在時間指定した秒数が経ってから
    📜 スクロール指定した％までスクロールしたら。滞在秒数と組み合わせると「◯秒後かつ◯％スクロール」になります
    🛒 カート追加カートに入れたとき。別途スニペットの設置が必要です（画面に表示されます）

    URL条件

    条件を入れなければ全ページで配信されます。複数の条件を追加できます。

    モード意味例
    このページだけ（完全一致）そのURLと完全に一致するページのみ/ ならトップページだけ
    このページ以下すべて（前方一致）そのパスで始まるすべてのページ/products で商品ページ全部
    URLのどこかに含む指定した文字列を含むページsale を含むURL全部
    トップページだけに出したいとき

    完全一致で / を指定してください。前方一致の / はすべてのページに一致してしまいます。

    配信スケジュール・繰り返し・時間帯

    設定できること
    配信スケジュール開始日時・終了日時。期間外は配信されません
    繰り返し：毎日既定。曜日・日にちの制限なし
    繰り返し：毎週曜日を複数選択（例 土・日だけ）
    繰り返し：毎月日にちを複数選択。月末も選べます
    時間帯1日のうちの時間を限定。タイムセールに使います
    毎月29〜31日の指定に注意

    2月など、その日が無い月があります。毎月確実に出したい場合は「月末」を選んでください。曜日・日にちを1つも選ばないと「毎日」として保存されます。

    表示頻度

    同じ人に何度出すかを決めます。既定は「ページを開くたび」です。

    単位選べる間隔
    ページビュー毎回 / 3ページビューごとに1回 / 5ページビューごとに1回
    セッション毎セッション / 3セッションに1回 / 5セッションに1回。「同じセッション内では1回だけ」も選べます
    ユーザー一生1回だけ / 最大3回 / 最大5回

    ③ 誰に表示？

    訪問者条件・ターゲット設定

    条件選択肢
    訪問回数N回以上。集計期間も指定できます
    流入元フィルター特定の流入元から来た人だけに絞る（任意）
    訪問種別すべて / 新規 / リピート
    デバイスすべて / PC / スマホ
    ログイン状態すべて / ゲスト / 会員
    カート状態すべて / 空 / 商品が入っている
    UTM条件utm_source などをカンマ区切りで指定
    属性条件質問接客の回答で絞る（7章）
    天気・気温条件アクセス地点の天気・気温で絞る
    除外条件この条件に当てはまる人には出さない

    A/Bテスト

    パターンを複数作り、それぞれに別のアクションを割り当てます。どのパターンを出すかはサーバー側で決まり、同じ人には同じパターンが出ます。成果はダッシュボードの「バリアント別集計」で比較できます。

    確認するときはシークレットウィンドウで

    同じ人には同じパターンが出るため、通常のウィンドウで何度開いても別パターンは見られません。シークレットウィンドウを使ってください。

    コンバージョン条件

    条件何をCVと数えるか
    🛒 購入完了購入をCVとして数えます
    🖱️ クリックCVCTAのクリックをCVとして数えます
    URL前方一致/thanks などで始まるページに到達したらCV
    URLパス完全一致指定したパスと完全一致で到達したらCV
    URL部分一致URLに文字列を含むページに到達したらCV

    あわせて「見た後にCVページへ遷移でCV計上」「クリックした後にCVページへ遷移でCV計上」を選べます。

    CV数は条件によって意味が変わります

    クリックCVのシナリオでは、CV数はクリック数です。購入数ではありません。施策ごとにCV条件が違うと数字の意味も変わるので、比べるときは条件をそろえてください。

    優先度

    数字が大きいほうが優先されます

    「1」がいちばん強いのではありません。優先度 10 と 1 なら 10 が勝ちます。

    そして優先度が効くのは同じ表示場所を使うシナリオが競合したときだけです。表示場所が違えば、複数のシナリオが同時に出ます。つまり「同じページで2つの施策が両方出る」のは正常な動きです。重ねたくない場合は、同じ表示場所を使うようにしてください。

    メモ

    施策の意図を書いておく欄です。「Topで初回訪問者にクーポン訴求 / Aは画像あり、Bは画像なし」のように残しておくと、数か月後に見返したときに助かります。

    07質問接客

    お客様に質問して、その回答を属性としてためていく機能です。ためた属性は、次の接客の条件に使えます。

    設定する項目

    項目内容
    質問文お客様に見せる文言
    回答形式単一選択 / 複数選択
    保存する属性キー回答をどの名前で保存するか。シナリオの属性条件でこのキーを指定します
    選択肢表示名と保存値をペアで登録します
    お礼回答後に出すメッセージ
    再表示回答済みの人への扱い。「再表示しない（1回のみ）」か「一定期間後に再質問」
    デザイン・クリエイティブ見た目の型とトンマナ

    使いかたの流れ

    1. 質問接客で質問を作り、保存する属性キーを決めます（例 taste）。
    2. シナリオの「① 基本」でその質問を選び、配信します。
    3. 回答がたまったら、別のシナリオの「③ 誰に表示？ › 属性条件」でそのキーの値で絞り、回答に合わせた接客を出します。

    08ダッシュボード

    施策の成果をまとめて見る画面です。最初に見る数値だけを上に出しています。

    ブロック見られること
    今日見るべき3指標まずここだけ見れば状況がわかる数値
    施策比較：シナリオ別 CVR / CTR施策どうしの比較
    日別トレンド：表示回数 × CVR%日ごとの推移
    施策別の詳細（表）表示・クリック・CV・売上の内訳
    バリアント別集計A/Bテストのパターン別成績
    流入計測と数字が違って見えるとき

    ダッシュボードのCVは、購入時にサーバーが確定した帰属だけを数えます。流入計測の一部の表には、参考値として「接触ベース」の数字も出ます。どちらも間違いではなく、数え方が違います。

    09流入計測

    サイト全体のアクセスと売上を見る画面です。6つのタブに分かれています。期間は画面上部で切り替えます。

    タブ見られること
    概要PV・セッション・ユニーク訪問者の推移、新規/リピート、売上
    流入流入元ごとのセッションと売上、直帰率、離脱ページ
    ページページ別のPVと離脱率、経由ページの売上貢献
    施策施策ごとのCVトレンド、クーポン経由の実績
    訪問者匿名IDごとの行動履歴。1人を選ぶと行動タイムラインが出ます
    環境デバイス・地域・天気などの内訳

    訪問者タブの見かた

    訪問者カードを選ぶと、その人のPV・クリック・購入が時系列で並びます。タグとメモを付けられるので、気になる訪問者を追いかけられます。

    「直近◯人」と出ている場合

    アクセスの多いサイトでは、期間中の全員を読み込むと時間がかかりすぎるため、表示する人数ぶんで読み込みを止めています。画面に「直近◯人（◯月◯日以降）」と出ます。期間を短くすると全員が表示されます。PV・売上・流入元などの集計値はこの影響を受けません。

    数字を読むときの注意

    見ている数字知っておくこと
    当日の数値集計途中です。グラフでは中抜きの点で示されます
    ユニーク訪問者（期間合計）日ごとのユニークの足し算です。期間全体での重複は除かれていません
    流入元の売上に出る「(流入元不明)」購入した日に閲覧ログが無かった購入です。別の日に見て後日買った場合などに入ります
    流入元が google と www.google.com で分かれるUTMパラメータ由来と参照元ドメイン由来で別枠になります。合算は手元で行ってください
    新規/リピートの内訳合計（＝ユニーク訪問者）は正確です。内訳の絶対数は多めに出ることがあります

    10週次レポートメール

    先週の成果をまとめたメールを、決めた曜日・時刻に自動で送ります。AIによる要約コメントも付けられます。

    1. 流入計測の画面からレポート設定を開きます。
    2. 配信をONにして、曜日と時刻を選びます。
    3. 宛先メールアドレスを登録します（複数可）。
    4. AIコメントを使うかを選びます。
    5. プレビューで中身を確認し、テスト送信で実際のメールを見てから保存します。

    レポートに入るのは、主要指標の前週比、売上の内訳、施策別の成績、流入元の上位です。AIコメントは数字の事実から書かれ、根拠のない予測や煽りは入らないようにしています。

    11AIインサイト

    施策の結果をAIが読んで、気づきと次の打ち手を出します。

    機能内容
    運用アシスタント成果データから気づきと改善案を出します。「AI分析を実行」を押すと生成されます
    バリエーション文言の言い換え案を出します。A/Bテストのネタ出しに
    実画面レビュー実際の表示を見て、改善点を画面上のピンで指摘します

    出てきた内容は提案です。そのまま配信されることはないので、採用するかはご自身で判断してください。

    12Webプッシュ BETA

    ブラウザのプッシュ通知を送る機能です。まず購読を集めてから、通知を送ります。

    購読を集める

    1. テンプレートで「プッシュ通知」タイプのものを用意します（標準テンプレートにあります）。
    2. そのテンプレートでアクションを作ります。
    3. シナリオで配信します。お客様の画面に購読を確認するダイアログが出て、許可すると購読されます。

    通知を送る

    サイドメニューの Webプッシュ から、購読者数を確認して送信します。タイトル・本文・クリック先URLを入れ、すぐ送るか日時を予約します。

    ベータ機能です。先に制約を確認してください
    • iPhone・iPadはほぼ届きません。 iOSはホーム画面に追加したPWAでしか受信できません。Safariのタブで開いているだけでは購読できません。
    • Shopifyでは通知の送信元がMOKKEDAのドメインになります。 Shopifyの仕様上、お店のドメインで通知を出せないためです。
    • Android・PCでは問題なく購読・受信できます。まずはこの2つを対象に考えてください。

    13メディア

    接客で使う画像を置いておく場所です。

    「メディアを追加」からアップロードすると、ダウンロードURLが発行されます。このURLをアクションの画像欄やテンプレートに貼って使います。各メディアには使用箇所（アクション）が表示されるので、どこで使われているか分からないまま削除してしまう事故を防げます。

    削除する前に

    使用箇所に名前が出ているメディアを削除すると、そのアクションの画像が表示されなくなります。先に使用箇所を確認してください。

    14Shopify連携

    MOKKEDA CONNECT アプリを使うと、テーマを編集せずにSDKを設置できます。

    1. Shopify管理画面からMOKKEDA CONNECTアプリを開きます。
    2. アプリが自動でストアを認証し、MOKKEDAと接続します。
    3. SDKがストアに自動登録されます。テーマへのタグ貼り付けは不要です。
    アプリを開かなくても計測は止まりません

    接続トークンは24時間で期限が切れますが、SDKはすでにストアに登録されているため、計測と接客はそのまま動き続けます。トークンが必要になるのはSDKを再登録するときだけです。期限切れの表示が出ていても、慌ててアプリを開く必要はありません。

    テーマに直接貼りたい場合は、2章のShopify用タグを使ってください。アプリと両方入れると二重に計測されるので、どちらか一方にしてください。

    15楽天RMS

    楽天市場店の売上データを取り込む機能です。この機能が有効なワークスペースだけメニューに出ます。

    1. RMSを設定するサイトを選びます。
    2. 設定タブでRMSの認証情報とショップURLを登録します。
    3. 同期を実行します。以降は自動で同期されます。

    取り込むと、商品データ（最大200件）と直近30日の商品別売上TOPが見られます。「データがありません。同期を実行してください」と出る場合は、まだ一度も同期されていません。

    16メンバーと権限

    ワークスペースに人を招いて、見える範囲を分けられます。

    招待する

    1. 設定 › メンバー を開きます。
    2. メールアドレスとロールを指定して招待します。招待メールが届きます。
    3. 相手がメールのリンクから承認すると、メンバーになります。

    4つのロール

    ロールできること
    オーナーすべての操作。契約・Billingの変更もできます
    管理者ワークスペース削除とBillingを除く、ほぼすべての操作
    メンバー担当サイトの閲覧・編集。シナリオとアクションは作れますが、テンプレートとメディアは触れません
    閲覧者担当サイトの閲覧のみ。設定は変更できません

    画面ごとの権限

    画面オーナー管理者メンバー閲覧者
    ダッシュボード✓✓✓✓
    流入計測✓✓✓✓
    シナリオ✓✓✓✓
    アクション・質問接客✓✓✓—
    テンプレート✓✓——
    メディア✓✓——
    AIインサイト✓✓✓✓
    サイト✓✓✓✓
    メンバー✓✓——
    ワークスペース✓———
    契約 / Billing✓———

    サイト単位の担当わけ

    オーナーと管理者は、ワークスペース内のすべてのサイトを見られます。メンバーと閲覧者は、担当として追加されたサイトだけが見えます。担当の追加はサイト詳細の「メンバー管理」から行います。

    契約 / Billing

    オーナーだけがアクセスできます。現在のプランの確認、プラン変更、請求先メールと住所の登録、支払い方法の変更ができます。

    17困ったとき

    接客が表示されない

    上から順に確認してください。多いのは2と4です。

    1. タグが入っているか。 表示したいページのソースに sdk.js があるか見てください。
    2. シナリオが稼働状態か。 下書き・停止中では配信されません。
    3. アクションがシナリオに追加されているか。 アクションを作っただけでは出ません。
    4. 表示頻度で止まっていないか。 「一生1回だけ」などにしていると、自分はすでに見たことになっています。シークレットウィンドウで確認してください。
    5. URL条件が合っているか。 トップだけに出したいなら完全一致の / です。
    6. スケジュール・繰り返し・時間帯の範囲内か。 曜日や時間帯を設定していると範囲外では出ません。
    7. アクションをアーカイブしていないか。 アーカイブ済みは配信されません。
    8. 同じ表示場所で優先度の高いシナリオに負けていないか。 数字が大きいほうが勝ちます。

    同じページで2つの施策が両方出てしまう

    仕様です。表示場所が違えば複数のシナリオが同時に出ます。重ねたくない場合は、同じ表示場所を使うようにして、優先度で勝ち負けを決めてください。

    売上が計測されない

    サンクスページ（購入完了ページ）にタグが入っているかを確認してください。ここが抜けていると購入と売上が記録されません。Shopifyでアプリ連携している場合は自動で入ります。

    クーポン経由の売上が出ない

    アクションにクーポンコードを登録しているか確認してください。登録がないと、クーポン一致による売上の紐づけができません。

    A/Bテストで片方のパターンしか見られない

    同じ人には同じパターンが出る仕様です。シークレットウィンドウを使ってください。

    流入計測の数字がダッシュボードと合わない

    数え方の違いです。8章と9章を確認してください。CV条件が施策ごとに違う場合も、数字の意味が変わります。

    プッシュ通知が届かない

    相手がiPhone・iPadの場合、ホーム画面に追加したPWAでなければ受信できません。Android・PCで試してください。
